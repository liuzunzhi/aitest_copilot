## 3. 关键设计

### 3.1 目标结构

```
顶层 Tabs（8 个）
├── 概览       → ProjectTodoCard + Descriptions（不变）
├── 文档       → Space vertical
│                ├── ProjectDocumentsTab        （零改动）
│                └── Card「版本快照」
│                     └── ProjectBaselinesTab    （零改动，props 不变）
├── 基线管理   → ProjectBaselineManagementTab（只改注释）
├── 增量分析   → ProjectIncrementalTab（零改动）
├── 测试点     → ProjectTestPointsTab（零改动）
├── 测试用例   → ProjectTestCasesTab（零改动）
├── 自动化执行 → ProjectAutomationTab（零改动）
└── 成员       → ProjectMembersTab.tsx（新）
                 └── 二级 Tabs（defaultActiveKey="members"）
                      ├── 「成员列表」  → member-table + 添加成员 Modal
                      └── 「加入申请」  → application-table
```

### 3.2 「版本快照」的刷新链路：一个字节都没动

```
文档上传 / 确认生效
  → ProjectDocumentsTab.onChanged()          ← 不动
  → ProjectDetailPage.reloadOverview()        ← 不动
  → setBaselineKey((key) => key + 1)          ← 不动
  → ProjectBaselinesTab 的 refreshKey 变化     ← 不动（props 没变）
  → useEffect([reload, refreshKey]) 触发重载   ← 不动
```

`ProjectBaselinesTab` 在「文档」Tab 内**始终挂载**（antd `Tabs` 的
`destroyOnHidden` 默认 false，切 Tab 不卸载组件），
所以用户**不需要来回切 Tab**就能看到快照刷新——**比旧的「版本快照」独立 Tab 更好**。

这直接让 e2e `test_ac_54_new_version_archives_old_and_baseline_refreshes`
的「**不刷新页面**，基线表应已重载」断言**原样成立**——
断言内容一个字没动，只把导航路径从「切到版本快照 Tab」改成「在文档 Tab 里直接看」，
**顺带把用例简化了**：原先要来回切 3 次 Tab，现在全程在「文档」Tab 里。

### 3.3 「成员」是受控组件（避免循环依赖）

```tsx
// ProjectMembersTab.tsx —— 子组件不持有 members/applications，也不发请求
interface Props {
  members: Member[]          // ← 父组件持有
  applications: Application[] // ← 父组件持有
  canManage: boolean          // ← 父组件判定（依赖 myRole → members）
  onSubmitAddMember: (...) => Promise<boolean>
  onChangeRole: (...) => Promise<void>
  onRemoveMember: (...) => Promise<void>
}
```

**为什么不能反过来**：`canManage` 判定依赖 `myRole`，`myRole` 来自 `members`——
把 `members` 放进子组件会让父组件拿不到角色，**形成循环依赖**。
副作用（也是收益）：**不重复请求成员列表**（否则进「成员」Tab 会打两次
`GET /api/projects/{id}/members`）。

**保留在父组件的**（一个字节都没动）：

| 内容 | 原因 |
|---|---|
| `members` / `applications` state | 受控传参 + `myRole` 权限判定 |
| `reloadMembers` / `reloadApplications` | 页面级生命周期 |
| `reloadApplications` 的 `catch {}` 静默降级 | 非管理员进「加入申请」**显示空列表、不弹 403 toast** |
| `canManage` / `canWrite` | `myRole` 依赖 `members` |
| `baselineKey` + `reloadOverview` | 快照刷新链路 |

### 3.4 二级子菜单：与「基线管理」完全同构

不是新发明，照抄 10 期 T122 已有的约定：

| 约定 | 基线管理 | 成员（本期） |
|---|---|---|
| 二级 Tabs 用 `defaultActiveKey`（非受控） | `defaultActiveKey="function"` | `defaultActiveKey="members"` |
| 外层容器带 `data-testid` | `process-baseline-subtab` | `project-members-subtab` |
| 每个 label 用 `<span data-testid>` 包裹 | `process-baseline-subtab-function` | `project-members-subtab-members` |
| 默认停在第一个子 Tab | 功能基线 | 成员列表 |

**为什么默认停在「成员列表」**：`member-table` 在 `test_smoke.py` /
`test_projects_ui.py` / `test_access_ui.py` 三处既有 e2e 里被直接断言「可见」——
`defaultActiveKey="members"` 让这 3 处**零改动**（只需给定位加 `exact=True`）。

### 3.5 403 静默降级保留

`GET /api/projects/{id}/applications` 对非 project_admin 返回 403。
合并进「成员」Tab 后，`reloadApplications` 的 `catch {}` **一个字节都没动**——
普通成员点「加入申请」看到**空列表**，**不弹 403 toast**。

### 3.6 「添加成员」失败时弹窗保持打开

原实现里 `setAdding(false)` 在 `try` 内、API 调用成功之后；
拆成受控组件后子组件拿不到「成功还是失败」→
`onSubmitAddMember` 改成**返回 boolean**，父组件 `catch` 分支返回 `false`，
子组件据此决定关不关弹窗。**用户能直接改值重试**——这是个容易丢掉的原行为。

## 8. 踩坑与修复

| 坑 | 处理 |
|---|---|
| **`tsc` 的 `noUnusedLocals` 因迁移残留变量而构建失败** | 迁移对照表逐项清空父组件。实际挡了 **3 处**：① 子组件的 `projectId` prop 没用上——**去掉**（handler 在父组件闭包里已带 `projectId`）；② 父组件的 `Button` / `Table` import 迁走后没人用了——**删掉**。**这是本任务最容易踩的坑**：`npm run build` 会**直接失败**，不报「哪个变量」，只报 TS 错误码 |
| **Playwright 的 `get_by_role(name=)` 默认是「子串匹配」** | `exact=False` → 属性选择器带 `i` 标志（`playwright/_impl/isomorphic/string_utils.py`）。顶层「成员」与内层「成员列表」**名字互相包含** → 裸写法在「成员」Tab 正激活时命中 **2 个** → **strict mode violation**。**统一写 `exact=True`**；内层子 Tab **用 `data-testid` 定位** |
| **antd 两层 `Tabs` 都用 `role="tab"`** | 顶层计数统一 `get_by_role("tablist").first.get_by_role("tab")`。**11 期实测纠正**：只有**当前激活**的顶层 Tab 的内层子 Tab 会被计入（已离开的面板是 `display:none`，Playwright 默认 `include_hidden=False`）→ 裸计数是 **8 + 2 = 10**，**不是 12**（10 期的「12」口径已过时） |
| **内层子 Tab 是懒渲染的** | antd `Tabs` 的 `forceRender` 默认 undefined，未激活的面板**不进 DOM**。所以「第一次点开某顶层 Tab」时裸写法**恰好安全**——但**依赖这个「恰好安全」很脆**，用例顺序一变就会撞。T126 把 4 处裸写法加固成 `exact=True`（**是加固，不是修 bug**） |
| **`test_t116_closing_ui.py` 的索引断言在点击循环之后** | 裸 locator 此时已有 10 个 tab，`nth(9)` 会命中**内层子 Tab**。把计数改成 `tablist.first` 后，索引断言**自动回到顶层语义** |
| **语义变化：「自动化执行」不再是最后一个 Tab** | 新顺序里「**成员**」是最后一个，「自动化执行」是倒数第二个。索引断言 `nth(9)/nth(8)` → `nth(7)/nth(6)`，注释同步改 |
| **`catch {}` 静默降级在拆组件时容易丢** | `reloadApplications` 的 `catch {}` 留在父组件——非管理员进「加入申请」**空列表、不弹 403 toast**。这条是 spec §2.3 第 4 条明确要求的 |
| **`onSubmitAddMember` 的返回值语义** | 拆成受控组件后子组件拿不到「成功还是失败」→ 改成**返回 boolean**，父组件 `catch` 返回 `false` → 弹窗**保持打开**，用户能改值重试 |
| **既有 flaky：`test_ac_214_process_baseline_full_flow`** | 在「文档反推」那步点 Select 选项超时。**T125 / T126 各撞到一次**（单跑与重跑均通过）——属 10 期遗留的时序抖动，与本期改动**无关**（该用例的代码 T124~T126 三次都没碰过）。按红线**没有动它**，登记到 Backlog |
