## 3. 关键设计（4 条）

### 3.1 不新建表，用 `source` 区分来源

复用 `document_chapter_links`（用户拍板）——既有数据、既有唯一键、既有列表接口、
既有前端全部不受影响。`source` 扩 `'ai'`：

| 来源 | 产生方式 | 重算口径 |
|---|---|---|
| `rule` | 正则抽取（「见第 2 章」） | 按 `source='rule'` 先删后插 |
| `manual` | 人工补链 | **永不受任何重算影响** |
| `ai` | 大模型分析 | 按 `source='ai'` 先删后插 |

**三种来源各自独立重算、互不覆盖。** AI 边命中人工边同一条时**跳过**
（否则撞 `uk_chlinks_to_chapter` 唯一键）。

### 3.2 引擎是纯函数

`link_analyze.analyze()` 的签名里**没有 `session`**——
「引擎不碰数据库」从「靠自觉」变成「结构上做不到」（对齐 10 期 `derive.py`）。

### 3.3 分块映射法

```
总正文字符 ≤ 30000  → 整篇一次调用
总正文字符 > 30000  → 阶段一：每 20 章一块，4 线程并发取「摘要 + 实体」
                      阶段二：全局目录清单（id + 标题 + 摘要 + 实体）做比对
```

**为什么**：整篇拼一个 Prompt 必然 token 溢出或让模型产生幻觉（几百章的大文档）；
但逐章调用又让模型看不到全局结构，跨章引用几乎必然漏掉。
分块映射法两头都占：阶段一压上下文，阶段二拿全局目录做比对。

**阶段一某块失败只跳过该块**（不整次失败）；全部块失败 → `LLMCallFailed`。

### 3.4 越界即丢 + 必给带 id 的清单

- Prompt 必给**带 id 的章节清单**（`章节#12 2.1 登录流程`）
- 服务层按 `chapter_ids` 校验，模型编造的 id **一律丢弃**
- 自引用、非法 `link_type`、重复边同样丢弃

**这是 06 期 L2 联调翻车的教训**：不给清单，模型就会自己编 `target_id=1`，
产出的结论全被当越界丢弃，整次分析跑完一条都没有。

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `.../links/analyze` | AI 分析（同步调真实大模型）→ `ChapterLinkAnalyzeOut` |
| DELETE | `.../links/{link_id}` | 删一条边 → 204 |

**响应体用 `ChapterLinkAnalyzeOut` 而不是裸 list**：前端要显示
「分析了 N 章，发现 M 条，丢弃 K 条越界」，还要区分
「模型没返回」与「返回了但全被丢弃」——裸 list 表达不了。
`mode` 字段（`full` / `chunked`）让用户知道走的哪条路。

## 5. 前端

| 用户诉求 | 落法 |
|---|---|
| 【✨ AI 一键分析引用】按钮在右上角 | `Drawer` 的 `extra` prop（`.ant-drawer-extra` 容器） |
| 源/目标章节 placeholder | 「请选择源章节」/「请选择目标章节」+ `showSearch` |
| 类型下拉选项说明 | 「引用 —— A 章节提到「见 B 章节」」等三项 |
| 实体名格式提示 | 「格式：功能:用户登录，如 功能:退款审核 / 术语:订单锁定」 |
| 顶部浅色提示语 | `Alert type="info"`，原文照用 |

**顺手修的 3 个既有缺陷**：
① `submitting` 一个 state 管两个按钮 → 拆成 `analyzing` / `extracting` /
`submitting` / `deletingId` 四个；
② 章节下拉无层级缩进 → 加全角空格缩进（对齐 `ProjectTestPointsTab`）；
③ `source` 三元表达式会把 `ai` 显示成「人工」 → 改用 `linkSourceTag()` 映射表。

**权限口径修正**（既有坑）：`canWrite` 含普通 member，但后端 `ensure_writable_admin`
只认 `project_admin` → 引用图写权限改用 `canManage`（新增 prop 往下传）。

## 9. 踩坑（3 个，都写进了 `PROGRESS.md` §4）

1. **antd v6 的抽屉没有 `.ant-drawer-content`**——v6 换成 `.ant-drawer-section`
   （面板）与 `.ant-drawer-body`（内容区）。用 v5 的类名定位会一直等到超时。
2. **抽屉的遮罩会盖住 Modal 的关闭按钮**——版本历史弹窗打开后再开抽屉，
   点 `.ant-modal-close` 被拦下超时。**不要试图关掉弹窗**，截图只截抽屉面板。
3. **并发下 `MockProvider.queue` 的消费顺序不确定**——阶段一并发调模型，
   断言「哪块拿到哪个响应」会随机挂。**按 Prompt 内容分派**而不是靠队列顺序。

另有 2 个设计修正记在 `tasks.md` §5：
模板缺失拆成 404 / 409 两个错误码；Mock 默认响应必须同时含 `chapters` 与 `references`
（两阶段共用一个前缀分流）。
