## 3. 数据模型

### 3.1 三张新表

- **`test_case_analyses`（生成记录）**：模板与版本快照、provider、依据的测试点批次、
  `status`（pending / running / succeeded / failed）、`error_code`、`stats`、起止时间。
  与 07 的 `test_point_analyses` 同构。
- **`test_cases`（用例）**：名称、类型（功能 / 接口 / UI）、优先级、前置条件、
  所属测试点（`test_point_id` + `test_point_name` 快照）、目标快照、章节快照、
  评审状态与意见、来源（llm / manual）、`source_point_fingerprint`、`needs_review_ack_at`。
- **`test_case_steps`（步骤子表）**：`step_no` + 操作 + 预期结果，
  `case_id` 外键带 `ON DELETE CASCADE`。

**关键决策**：

- **`test_point_id` 与 `test_point_analysis_id` 都不建外键**：07 的删测试点、删批次
  都是物理删除，建外键会把 07 的既有行为变成 500。这里用逻辑引用 + 落库快照。
  验证方式：07 的两个删除接口实测仍返回 204（`test_needs_review.py`）。
- **`source_point_fingerprint`（SHA-256）而不是 `updated_at`**：
  `test_points.updated_at` 只有 `server_default`，MySQL 方言不渲染 `ON UPDATE`，
  应用代码也从不赋值——拿它比对**永远不触发待复核**。
  指纹字段清单只在 `app/test_cases/fingerprint.py` 一处（生成 / 读取 / ack 三处共用）。
- **`updated_at` 由服务层显式赋值**：同一个 MySQL 方言问题。
- **步骤 `step_no` 由服务端按数组顺序重排**：不信模型给的序号。
- **`test_case_steps.case_id` 的 FK 带 `ondelete='CASCADE'`**（数据库级），
  删用例只 `session.delete(case)`。

### 3.2 迁移 `0023`

- `down_revision = "0022"`；按外键顺序建表，`downgrade` 反序直接删表。
- `llm_run_logs.task_type` 的 CHECK **先删后加**（MySQL 不支持直接改 CHECK）；
  三层验证：约束文本含 `'test_case'`、实插成功、插 `'bogus'` 被拒（3819）。
- 播种 1 条 active 模板（`[TEST_CASE_SYSTEM]` / `[TEST_CASE_USER]`）。
- **`downgrade` 先删 `task_type='test_case'` 的留痕行再收回 CHECK**：
  否则旧 CHECK 重建时会被留痕行撞 3819（07 期 T104 踩过同一个坑）。
- **模板示例里没有任何 id**：08 的输出契约不含测试点 id，
  06 期「模型照抄示例 id」的坑**从结构上消失**。

## 4. 架构与关键设计

### 4.1 输入口径

| 输入 | 口径 |
|---|---|
| 生成 | **只吃 `status='approved'` 的测试点**；显式给 id 时**严格**（任一不满足就 400，不静默过滤） |
| 手工新增 | **允许挂任意已存在的测试点**（含 pending / rejected）——人工补录不该被评审状态卡死 |
| 空输入 | 筛选后 0 条 → **400 `TEST_CASE_INPUT_EMPTY`**，不建生成记录 |

### 4.2 Prompt 三段式（可复现）

1. `template.user_prompt`（原样取库）
2. `## 测试点` —— 5 个字段固定出现（缺失写「（空）」，保证结构稳定）
3. `## 来源章节：{title}` + 正文（章节缺失 / 正文空白 → 整段不渲染）

截断只截**章节正文**，前缀逐字节不变。

### 4.3 输出契约（没有测试点 id）

```json
{"cases":[{"title":"…","case_type":"functional|api|ui","priority":"high|medium|low",
           "precondition":"…","steps":[{"action":"…","expected":"…"}]}]}
```

**绑定哪个测试点由服务端决定**（按「当前正在处理的测试点」）——
模型连要填哪个 id 都不知道，06 期的照抄坑从结构上消失。

### 4.4 模型输出校验（不猜、不修）

| 情况 | 处理 |
|---|---|
| `cases` 不是数组 / 坏 JSON | 整次失败（复用 `parse_llm_json`） |
| 缺 `title` / `steps` 空 / `action` 空 | 整条丢弃，计入 `stats.discarded` |
| 同测试点内重复 `title` | 保留第一条（顺序确定） |
| `case_type` / `priority` 非法 | **归一到 functional / medium**，不丢 |
| `expected` / `precondition` 缺失 | 存空串，不丢 |
| 超长文本 | 按列宽截断（255 / 1000），不丢 |

### 4.5 待复核（读时派生，不落库）

```
指纹字段（10 个）：name / target_type / target_id / target_name / priority /
                  precondition / verification / chapter_id / chapter_title / needs_review
```

- 源测试点不存在 → 快照非 NULL → `needs_review=true`，`source_point_deleted`；
  快照为 NULL → 已人工确认删除，不再提示。
- 源测试点存在 → 指纹不等 → `needs_review=true`，`source_point_changed`。
- **`needs_review` 是响应字段**，库里没有这一列；筛选在 Python 层做。

**为什么指纹里含 `needs_review` 位**：07 因标签清除把测试点置 `needs_review=1`
也会改变指纹 → 08 同样标「源已变更」。**08 不 import 04 / 05 的任何模块**。

### 4.6 步骤整体覆盖

**先校验整组再动手**：空数组 / `action` 空 / 超过 100 步 → 400
`TEST_CASE_STEP_INVALID`，**原步骤一条不变**（整体事务）。

## 5. 接口一览

前缀 `/api/projects/{project_id}/test-cases`，8 条路径 / 13 个接口：

| 方法 | 路径 | 权限 |
|---|---|---|
| GET / POST | `/analyses` | 成员 / 项目管理员 |
| GET / DELETE | `/analyses/{id}` | 成员 / 项目管理员 |
| GET | `/cases` | 成员（筛选：状态 / 测试点 / 目标 / 批次 / 待复核） |
| POST | `/cases` | 项目管理员（手工新增） |
| GET | `/cases/export` | 成员（`.xlsx`，一步一行） |
| GET / PATCH / DELETE | `/cases/{id}` | 成员 / 项目管理员 |
| PUT | `/cases/{id}/steps` | 项目管理员（整体覆盖） |
| POST | `/cases/{id}/review` | 项目管理员 |
| POST | `/cases/{id}/ack` | 项目管理员（确认已复核） |

校验顺序固定：**404 → 409（归档）→ 403（角色）→ 400（业务）→ 跑模型**。

> `/cases/export` **必须注册在 `/cases/{case_id}` 之前**——FastAPI 按注册顺序匹配，
> 写在后面会被路径参数吞掉（`export` 被当 id 解析成 422）。

## 9. 踩坑与修复

| 坑 | 处理 |
|---|---|
| `test_points.updated_at` 在 MySQL 下**不生成 `ON UPDATE`** | 改用 SHA-256 内容指纹；`test_cases.updated_at` 由服务层显式赋值 |
| 建外键会让 07 的物理删除变 500 | `test_point_id` / `test_point_analysis_id` 都不建外键，只做逻辑引用 + 快照 |
| 审计列是 JSON 列，塞 `datetime` 直接 500 | `ack` 审计里的时间改 `isoformat()` |
| pydantic 静默丢未知字段 | `CaseUpdate` 用 `extra='allow'` + 服务层拦截只允许 4 个可改字段 |
| 路由注册顺序 | `/cases/export` 必须在 `/cases/{case_id}` 之前 |
| 模板默认值竞态：模板列表回来前就点提交 → 「模板必填」静默拦下 | 模板先落位、挂靠下拉异步补；e2e 等模板落位再提交 |
| 抽屉是 fixed + transform 滑入，整页截图裁掉半截 | `shot(..., full_page=False)` |
| 抽屉动画期间元素「可见」但未落位 | 新增 `wait_drawer_settled`（等它完整进视口，不猜 antd 内部类名） |
| 宽表在 1280 视口下操作列溢出 | T109 用 1600 宽的 `wide_admin_page` 夹具 |
| e2e 直写库造用例 → 指纹为 NULL，待复核永远真 | 改走真实接口 `POST /cases`，服务端会写指纹 |
